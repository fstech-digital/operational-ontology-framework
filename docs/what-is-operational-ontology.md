# What Is Operational Ontology?

Operational Ontology is a structured representation of the data, logic and actions that govern a real operation.

It is not only a vocabulary or knowledge map. It answers three connected questions:

1. What entities and states exist?
2. Which rules and exceptions govern decisions?
3. Which actions may be proposed or executed, under whose authority?

The goal is not to make an AI system sound informed. The goal is to prevent it from inventing operational context when decisions have consequences.

## Descriptive Versus Operational

A descriptive model explains a domain. An operational model also establishes boundaries for decisions, action and write-back.

That does not imply unrestricted autonomy. In high-impact contexts, the correct action may be to prepare a proposal, request approval, escalate an exception or block execution.

## Minimum Test

A model is operationally useful only when a reviewer can determine:

- which source informed the decision;
- which rule was applied;
- which authority permitted the action;
- which evidence shows the result;
- which state must be preserved for the next session.

The implementation of those controls is context-specific and is not published in this repository.
